# Matrix server

Модульный Node.js/gRPC backend для Electron-клиента. Python собирает plain-индексы
Manticore из исходных таблиц настроенной MariaDB. Операционная
MySQL 8.4 (`matrix`) хранит каталог `data_base`, рабочие записи и журнал API.
Исходные наборы остаются на отдельном сервере; рабочие таблицы и журнал не индексируются.

Это самостоятельный репозиторий backend, без зависимостей Electron/Vue.
Адреса серверов, секреты и пути данных задаются локальной конфигурацией.

## Локальная разработка

Нужен Node.js 24 или новее (`engines.node >=24`). Из корня репозитория:

```bash
npm ci
npm test
node --check node/main.mjs
python3 -m unittest discover -s tests
python3 -m py_compile scripts/build_manticore_indexes.py
node scripts/checkPublication.mjs
```

Проверка публикации читает текущие отслеживаемые и неигнорируемые файлы и выводит
только пути, номера строк и виды находок. Локальные секреты, сертификаты, данные
и рабочие планы остаются вне Git.

История репозитория начинается с чистого снимка исходников без прежних сведений об
окружении. Публиковать можно непосредственно этот репозиторий; отдельный экспорт
исходников не требуется. Перед публикацией выполните проверки выше и убедитесь,
что адрес Git remote соответствует нужному репозиторию.

Если удалённая ветка уже содержит прежнюю историю, её замена требует отдельного
согласованного обновления удалённого репозитория. Локальная очистка сама по себе
не изменяет GitHub и другие существующие копии.

Для ручного запуска скопируйте `.env.example` в `.env`, замените ключи и выполните
`node --env-file=.env node/main.mjs`. По умолчанию пример включает `search,catalog`,
оставляет `MATRIX_MYSQL_HOST` пустым и позволяет запуск без MySQL. Каталог читается
из опубликованного JSON, а поиск требует доступной Manticore и готовых индексов.
Тесты используют локальные заглушки и не обращаются к исходным базам.

Для операционного каталога настройте `MATRIX_MYSQL_HOST/PORT/USER/PASSWORD/DATABASE`,
выполните `npm run migrate`, затем включите
`MATRIX_MODULES=search,catalog,workspace,records`. Для workspace требуется отдельный
`MATRIX_ADMIN_API_KEY`, отличный от поискового `MATRIX_API_KEY`. Изменение схемы
выполняется только явной миграцией. Пароль MySQL можно передать через
`MATRIX_MYSQL_PASSWORD_FILE`, убрав переменную `MATRIX_MYSQL_PASSWORD` целиком.
`npm run migrate` и `npm run catalog:copy` загружают локальный `.env`, если он есть;
копирование каталога выполняйте только явно после настройки отдельного источника.

## Модули и контракты

- `node/core`: конфигурация, регистрация модулей, gRPC, авторизация и жизненный цикл.
- `node/modules/search`: совместимый поиск, поток результатов, отмена, статус индексов.
- `node/modules/catalog`: существующий RPC каталога; MySQL или опубликованный снимок.
- `node/modules/workspace`: административный CRUD `data_base` и `work_items`,
  чтение `service_logs`; только явно зарегистрированные ресурсы и поля.
- `node/modules/records`: таблица `control` в рабочей MySQL и API вкладки
  «Записи», включая потоковые вложения. [Контракт и хранение файлов](docs/control-records.md).
- `node/infrastructure/mysql` и `migrations`: параметризованные запросы и версии схемы.
- `scripts/build_manticore_indexes.py`: независимые подключения к каталогу и источнику,
  возобновляемые шарды, проверка `indextool`, публикация после сетевого reload.

Существующие search/catalog protobuf-контракты сохранены. Контракт workspace —
`protos/workspace.proto`, сервис `matrix.workspace.v1.Workspace`: `ListRows`,
`GetRow`, `CreateRow`, `UpdateRow`, `DeleteRow`. Все запросы содержат явно разрешённый
`resource`: `data_base`, `work_items` или `service_logs`; журнал доступен только для
чтения. `Row` содержит `id:string` и `values:map<string,string>`, список — `rows` и
`total:string`. Поисковый ключ не открывает административные RPC. Примеры запросов
и ограничения — в [описании CRUD](docs/deployment.md#административный-crud).
Новые API-модули регистрируются явно; инструкция расширения — в
[deployment.md](docs/deployment.md#расширение-api).

Каждая исходная строка становится документом Manticore. Поисковые поля индексируются,
полная исходная строка хранится в сжатом stored-only поле. Идентификатор документа
включает ID каталога, поэтому при копировании `data_base` ID сохраняются. `id` и
`name_table` нельзя изменять обновлением. После публикации непустого снимка API также
защищает занятые ID от удаления/повторного создания; новые записи требуют явного
свободного ID. Изменение метаданных не обновляет замороженные план и поисковый снимок.
Добавление/исключение исходной базы требует согласованного обслуживания и новой
генерации индексов, а не простого перезапуска индексатора.

Поиск по умолчанию ищет точную фразу. Введённые пользователем `%` и `?` становятся
масками (`%` → `*`). Результаты передаются потоком; `MATRIX_SEARCH_PAGE_SIZE`
ограничивает размер страницы, а не общее число совпадений.

## Будущая выкладка Docker Compose

Подготовлены Node.js 24 API, MySQL 8.4, одноразовая миграция, Manticore и отдельный
индексатор профиля `indexing`. Копирование только каталога — явная задача профиля
`tools`. Обычный `up` не копирует каталог и не запускает индексацию. Пустой каталог
допустим; поиск по исходным данным появится после явной сборки индексов.

API получает только публичное состояние индекса read-only и TLS-каталог. Исходные
пароли и private-конфигурация индексатора ему не передаются. Порты MySQL/Manticore
не публикуются; gRPC по умолчанию доступен только на localhost. Перед доступом из
LAN необходимо настроить TLS и отдельные ключи.

Полная последовательность подготовки, копирования каталога, индексации, резервного
копирования и проверок: [docs/deployment.md](docs/deployment.md).

Для проверки шаблона без запуска контейнеров:

```bash
docker compose --env-file .env.compose.example config --quiet
docker compose --env-file .env.compose.example --profile indexing --profile tools config --quiet
```

Образы и реальные БД требуют отдельных проверок на будущем Docker-хосте.
Этот этап не включает сборку образов, запуск Docker daemon, выкладку или доступ к
исходному серверу. `scripts/install_server.sh` и `systemd/*` относятся к native
выкладке в `/opt/matrix`; они не являются установщиком этого Compose.
